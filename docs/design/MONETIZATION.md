# 課金設計（制度・商品・ユーザーストーリー・導線）

この文書は「何を売るのか」「誰がどういう経緯で払うのか」「その経路をどこに置くのか」を
一つに繋げて記述する。**数値はすべて実装からの引用**で、提案は(提案)と明記する。

関連: `REVENUE-ANALYSIS.md`（現状の収益構造の事実）/ `NAVIGATION-FLOW.md`（遷移グラフ）/
`UX-DESIGN.md`（UX全体の設計思想）

## 1. 制度の骨格

### 1.1 二つの圏

```
名声圏（緑）  ギルドコイン    活動（PRマージ）で得る。買えない
課金圏（琥珀） ルーン          円で買う。活動では得られない（無償付与を除く）
```

**この分離は崩さない。** ギルドコインを売ると「働いた対価」が金で買えることになり、
名声圏の意味が消える。逆にルーンを活動報酬にすると課金の対価が消える。

### 1.2 売るもの / 売らないもの

| | 判断 | 理由 |
|---|---|---|
| ルーン（前払式支払手段） | **売る** | 課金圏の唯一の入口 |
| 冒険者パス（月額） | **売る** | 継続収益の背骨 |
| ギルドコイン | **売らない** | 仕事の対価。買えると経済が壊れる |
| XP・レベル | **売らない** | 活動の記録そのもの |
| ストリーク保護 | **売らない** | 時間的ダークパターン（休めなくなる） |
| 順位・リーダーボード | **売らない** | 社会的ダークパターン |

### 1.3 ルーンの使い道（全て実装済み）

| 使い道 | 価格 | 出典 |
|---|---|---|
| 限定召喚 1回 | 30ルーン | `LimitedSummonRules.SINGLE_COST_RUNE` |
| 限定召喚 10連 | 300ルーン（割引なし） | `LimitedSummonRules.costFor` |
| スキン STD / DX / LG | 320 / 880 / 1,800 | `MonsterSkin.kt:71-73` ※**在庫0件** |
| 工房 モンスター track 累計 | 6,000 | `ForgeLevelCatalog` ※スキン必須のため実質未稼働 |
| 工房 バッジ track 累計 | 2,496 | `ForgeLevelCatalog` |
| 記念プレート | 200 | `COMMEMORATIVE_MINT_PRICE` |
| 属性魂パック S/M/L | 30 / 80 / 210 | `RuneSoulPackCatalog` |

## 2. 商品と価格（実装値）

### 2.1 ルーンパック `RuneProductCatalog.kt`

| SKU | 価格 | 付与 | ¥/ルーン | 備考 |
|---|---|---|---|---|
| rune_starter | ¥480 | 170 | 2.82 | **初回限定・おひとり様1回** |
| rune_60 | ¥240 | 60 | 4.00 | 最小 |
| rune_160 | ¥600 | 170 | 3.53 | |
| rune_340 | ¥1,200 | 380 | 3.16 | |
| rune_720 | ¥2,400 | 840 | 2.86 | |
| rune_1850 | ¥6,000 | 2,300 | 2.61 | |
| rune_3900 | ¥12,000 | 5,000 | 2.40 | 最大 |

高額ほど単価が安い（4.00 → 2.40）。**初回パックだけが小額で単価が良い**設計で、
最初の一歩を踏ませるための階段になっている。

### 2.2 冒険者パス `Subscription.kt:11`

**¥780/月（税込）**。特典と実装状況:

| 特典 | 実装 | 場所 |
|---|---|---|
| 月150ルーン付与 | ○ | `HandleSubscriptionWebhookUseCase`（**PSP webhook依存・§7参照**） |
| PRマージ時の相棒魂 ×2 | ○ | `AdventurerPassBenefits.partnerSoulMultiplier` |
| 通常召喚 天井 80→70 | ○ | ハード天井のみ（ソフト天井は60固定・§7参照） |
| 限定召喚 天井 60→50 | ○ | `LimitedSummonRules.isHardPity` |

150ルーンは最良レート換算で約¥360。**パス価格の46%**なので、残りは魂×2と天井短縮で
正当化する構造になっている。

### 2.3 限定召喚プールの中身（BE #308 で変更）

合計100・確率は開示APIからそのまま画面に出る。

| 枠 | 重み | 中身 |
|---|---|---|
| SSR | 1 | 目玉 Seasonal Debugger（**1%**・天井60回／パス50回で確定） |
| SR | 4 | 召喚専用モンスター4体（**各1%**） |
| R | 30 | 進化の輝石 |
| N | 65 | 魂パック・小 |

**モンスター出現は合計5%。召喚専用モンスターは激レア枠に限る。**
4回に1回出るような確率だと「専用」の意味が消え、天井まで引く理由も無くなる。
出現を絞る代わりに、天井で必ず届くようにしてある（絞っても到達不能にはしない）。

- 何かしらのモンスターが出るまで期待20回（600ルーン ≒ ¥1,560）
- 目玉は天井60回で確定（1,800ルーン ≒ ¥4,700／パスなら約¥3,900）

有料プールに置くモンスターは `prAcquirable = false` の召喚専用に限る
（PRで貰えるものを売っても対価にならない）。

### 2.4 課金の階段

```
¥0       PRをマージしてコインを貯める・通常召喚を引く・図鑑を埋める
 ↓       （ここで「あと1体」の対象＝召喚専用モンスターの存在を知る）
¥480     初回限定パック 170ルーン ＝ 限定召喚 5回
 ↓
¥780/月  パス（月150ルーン＋天井短縮＋魂2倍）
 ↓
¥1,200〜 単発パック（380ルーン ＝ 12回）
 ↓
¥4,700前後  天井まで引く（60回 × 30 = 1,800ルーン）※パスなら約¥3,900
```

天井到達コストが実質の上限価格。**ここを超える請求は設計上発生しない**
（在庫無限・複数天井を煽る仕掛けを置かない）。

## 3. ユーザーストーリー（課金に至る経緯）

Job Story 形式。`UX-DESIGN.md` の JS-1〜JS-6 の続き番号。

```
JS-7  図鑑に「召喚専用」と書かれた空き枠を見つけたとき、
      それがどうすれば埋まるのか知りたい。
      集めているものが完成しないのは気になるから。

JS-8  天井まであと何回かを見ているとき、パスで縮むなら知りたい。
      同じ回数を引くなら安く済ませたいから。

JS-9  ルーンを買った直後、すぐ引きたい。
      買ったのは引くためで、棚を眺めるためではないから。

JS-10 相棒に愛着が湧いたとき、その子を飾る手段と値段を知りたい。
      自分の相棒として見せたいから。（※スキン在庫0のため現在は満たせない）

JS-11 課金を続けるか決めるとき、今月いくら使ったか把握したい。
      使いすぎたくないから。

JS-12 未成年が課金しようとしたとき、上限で止まってほしい。
      家族に説明できない請求を作りたくないから。
```

## 4. ルート（各ストーリーの遷移）

### R-1 無料ユーザーが初めて払うまで（JS-7 → JS-8 → JS-9）

```

                 図鑑ヘッダに「うち召喚専用 N / M」

~/summon  ヘッダー直下の琥珀バナー

      ↓
~/summon/limited
      PITY COUNTER「あと48回でSSR確定（天井 60）」
      未加入なら「パス加入中は天井 50 回（10回少ない）」+ パスへ  ← JS-8
      ルーン不足なら BalanceShortfall → ~/shop/runes            ← 資金の壁
      ↓

      初回限定パック ¥480/170ルーン を先頭に表示
      年齢未申告なら年齢確認 → チェックアウト → KOMOJU
      ↓

      ↓
```

### R-2 パス加入（JS-8）

```

  「アドベンチャラーパス加入中は天井 50 回（10回少ない）」→ パスの内容を見る
```

### R-3 継続と自己管理（JS-11・JS-12）

```

  ウォレット（コイン / ルーン合計 / 有償 / 無償）+ 「ルーンを購入する →」
  パス状態（未加入 / 加入中 / 解約予定）+ 解約
  購入履歴（金額・状態・日時）
  年齢区分の再申告 → 当月上限が変わる

```

### R-4 相棒を飾る（JS-10・**現在到達不能**）

```
~/monsters の相棒カード → 「このモンスターのスキンを見る」
      ↓
~/shop/skins?monster=slug → 詳細 → 購入（ルーン）→ 装備 → ~/forge で深化
```

## 4.5 ショップの情報構造

APIは商品を**フラットな24件**で返す（属性魂パック18 + コイン商品6）。
これを24枚のカードとして並べると、ほぼ同じ見た目のボタンが大量に生えて
「何を選ぶ画面なのか」が読めなくなる。実際そうなっていた。

属性魂パックは**18種類の商品ではなく、1種類の商品 × 2つのパラメータ**である。

```
[ 魂パック ]  魂は相棒のレベルアップに使います
  属性を指定して付与
   [炎][水][雷][自然][光][闇]      ← 属性を選ぶ（6チップ）
    小   50魂を付与         30 ルーン
    中  150魂を付与         80 ルーン
    大  450魂を付与        210 ルーン   ← 選んだ属性の3行だけ出す
  ─────────────────────────
  魂パック・小   魂 5        500 ギルドコイン
  魂パック・中   魂 15     1,500 ギルドコイン
  魂パック・大   魂 30     3,000 ギルドコイン

[ 進化・路線変更 ]  進化と路線変更に使う素材です
  進化の輝石     Lv50で進化      2,000 ギルドコイン
  浄化の証       路線変更（覚醒）  5,000 ギルドコイン
  深淵の証       路線変更（暴走） 20,000 ギルドコイン
```

**24枚 → 2セクション（6チップ + 9行）。**

区切りは API の `category`（`SOUL_PACK` / `EVOLUTION`）に従う。
畳む判断は `variantGroup` / `attribute` / `sizeSuffix` に従い、
**itemId の文字列解析はしない**（BE #310 でメタデータを追加した）。
未知の category は落とさず「その他」に出す。

## 6. 制度上の制約（守るべきもの）

### 6.1 年齢別の月額上限 `AgeGroup.kt`

| 区分 | 当月上限 |
|---|---|
| UNDER_16 | ¥5,000 |
| AGE_16_17 | ¥20,000 |
| ADULT | ¥50,000 |

`CreateCheckoutUseCase.kt:136` で**チェックアウト時に強制**している
（当月購入額 + 今回の価格 ≤ 上限）。上限超過は決済前に止まる。

パスは成人のみ（`getPassCheckoutEligibility`）。

### 6.2 前払式支払手段としての表示

- ルーン残高は**概数表示にしない**（有償/無償の内訳を `mypage/billing` に出す）
- 資金決済法・特商法に基づく表示へのリンクを課金画面に常設
- 退会時のルーン失効はチェックボックス同意を取る

### 6.3 確率と価格の開示

- 価格・確率・天井は**すべてAPI由来**。フロントに定数を置かない
- 未取得のあいだは仮の値を出さず、何も出さないか `—`

## 7. 実装上のリスク（要対応）

| # | 内容 | 影響 |
|---|---|---|
| 7.1 | **パスの月150ルーン付与がPSP webhook到着時のみ**。内部スケジューラが無い（`HandleSubscriptionWebhookUseCase`） | 課金は継続するのにルーンが届かない。解約要因かつ前払式支払手段の表示問題 |
| 7.2 | 通常召喚の**ソフト天井はパスで短縮されない**（60固定 / `GachaSampler`） | パス保有者のブースト窓が10回、未加入者は20回。特典として説明しづらい |
| 7.3 | **スキン0件**（`monsterSkinSeedCatalog() = emptyList()`） | 320/880/1,800 と工房6,000が丸ごと未稼働。JS-10 が満たせない |
| 7.4 | `HeroPityCounter` に**パス非対応の天井定数の写し**がある（80/60） | 誤って参照すると加入者に長い天井が適用される |
| 7.5 | **計測が無い**（解析基盤ゼロ） | 課金到達率・離脱地点が測れず、以降の判断が推測になる |

## 9. コインの使い道（この方針の副作用）

モンスターを有料プールとPRマージに限定したため、**ギルドコインの使い道は
魂パックと進化素材だけ**になっている。実測で16,475コイン（＝未使用54回分）が
滞留していた事実がある（`REVENUE-ANALYSIS.md` §3）。

コインを売らない方針は維持するので、解決はコイン側の**吸収先を増やす**方向になる。
候補(提案):

- 通常召喚の景品を拡充（コスメではない、名声圏の記録物）
- 図鑑・バッジの達成に対するコイン消費の演出（額縁・称号など、購入ではなく交換）
- コイン獲得の上限開示（8.3）とセットで「貯める意味」を明示

いずれも課金圏と競合しない範囲に限る。
