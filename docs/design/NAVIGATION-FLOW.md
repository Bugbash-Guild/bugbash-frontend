## 2. 構造的な問題

### 2.1 補充の入口15本に対し、消費先の入口は1本

```
/shop/runes （ルーンを買う）          固有入口 15本
/summon/limited （ルーンを使う主戦場） 固有入口  1本
```

限定召喚は 30ルーン/回、天井60回で1,800ルーン（≒¥4,700）。
**ルーンの最大の吸収先**であるにもかかわらず、入口は `/summon` ページ内の1リンクのみ。
しかもその1本は召喚ページ最下部、「コインが足りないときは…」の注記の後ろにある
中立スタイルの全幅ボタンで、ページ内で最も弱い。

「補充」は過剰に案内し、「使う」は案内していない。**順序が逆**である。
使い道が見えないものを人は買わない。

### 2.2 単線が3本

`/summon/limited` `/badges` `/items` は入口が1本しかなく、その1本が消えると到達不能になる。

これは Progressive Disclosure として意図的にやったこと（`navConfig.ts` の方針）だが、
**適用対象を間違えた**。文脈から入るべきなのは「必要になったら探す機能」で、
`/summon/limited` は「見せたい商品」である。同じ扱いにしてはいけない。

### 2.3 行動した直後に行き先が無い

| 行動 | 直後の遷移（変更前） | 問題 |
|---|---|---|
| **ルーンを購入して決済から戻る** | `/shop`（コインのアイテム棚） | 買ったルーンを使えない棚に返していた。最も熱い地点で最も遠い場所へ送る |
| 限定召喚を引いた | 「図鑑で確認」/「閉じる」 | 天井まで引く前提の設計なのに「続けて引く」が無い |
| ショップでアイテムを購入 | 3秒で消えるフラッシュ | 買った魂パックをどこで使うのか（=モンスターのレベルアップ）に繋がらない。購入→何も起きない→離脱 |
| 通常召喚を引いた | 「図鑑で確認 →」 | ○ 繋がっている（図鑑側で直近24hに NEW） |
| パスに加入して戻る | `/pass` | ○ |

### 2.4 初回の10分に何も起きない

```
login → home → [GitHub App インストール] → 外部サイト（github.com）へ離脱
      → /github-app/callback → home → ■ここで停止■
```

停止地点でユーザーにできることが**ゼロ**。次に何かが起きるのは
「自分のPRが誰かにマージされたとき」で、待ち時間は制御不能。
さらに `FirstQuestChecklist` のステップ3「最初の相棒を迎える」CTAは `/summon` を指すが、
通常召喚プールにモンスターが入っていないため**そのCTAでは達成できない**
（`REVENUE-ANALYSIS.md` §4）。

初回体験の遷移が「外に出て、戻って、止まる」になっている。

## 3. 実施した変更

| 変更 | 意図 |
|---|---|
| `/billing/return` の完了状態で、ルーン購入なら **`/summon/limited` を第一CTA**（琥珀）に、`/shop` は副次に降格 | 決済直後の熱を使い道に繋ぐ |
| 限定召喚の結果モーダル「閉じる」→ **「続けて引く」** | 天井前提の設計に合わせる。文言だけで挙動は同じ（モーダルを閉じるとボタンの前に戻る） |
| ショップの購入成功を3秒フラッシュから **`InlineActionResult` + 「相棒に使う →」** に | 買ったものの使用先へ繋ぐ。消えない |
| 結果モーダルの `RUNE` → `ルーン` | 通貨名の統一（`formatSummonCurrencyLabel` と同方針） |

## 4. 未実施（判断が必要）

### 4.1 限定召喚を単線から外す — **実施済み（FE #146）**

サイドバーは6項目のまま維持し、経路を2本増やした:

- `/summon` ページのヘッダー直下に `LimitedSummonBanner`（琥珀）。開催名・単価・
  引ける回数のみ。最下部の弱いリンクは削除
- home の `NextActionStrip` を通貨ごとの行に拡張し、ルーン行から `/summon/limited` へ。
  判定は `buildNextActions`（純関数）で、**コイン行を必ず先に置く**ことをテストで固定

これで `/summon/limited` の固有入口は 1 → 3 本になった。

### 4.2 初回の待ち時間を埋める

根本解決はBE側（スターター付与、または通常召喚プールへのモンスター追加＝`REVENUE-ANALYSIS.md` P0）。
FE単独でできるのは、App導入直後に「次に何が起きるか・いつ起きるか」を明示する画面を出すこと。
現状は home に戻して黙っている。

### 4.3 工房からの戻り道

`/shop/skins` 詳細 → `/forge?skin=` に入ったあと、元のスキンに戻る導線は
`SkinTargetList` の「スキンカタログを見る」だけで、**これはスキン所持数0のときしか出ない**。
スキンが配信されたら塞がる。

### 4.4 モバイルの遷移

390px ではページ本体のグリッドが崩れて横に溢れる（`UX-DESIGN.md` の禁止事項に抵触）。
ナビはハンバーガーで届くが、遷移先が読めないので導線としては成立していない。
レイアウト対応が前提。
