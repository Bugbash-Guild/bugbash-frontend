# アート発注シート

これから描いてほしい（用意してほしい）画像の一覧。コードの調査結果に基づき、
**受け口が実在するものだけ**を、必要な仕様つきで並べている。

現状の入稿状況: モンスターは 49系統 × 6形態 = 294枚が入稿済みで完了。
未整備なのは以下（優先度順）。

---

## 共通仕様（全アセット）

- **PNG・正方形 1254×1254・透過（RGBA）**。既存モンスターと同じ規格
- キャラは中央配置、余白を均等に（表示は `object-contain` なので切れないが、
  枠によっては横長にトリミングされて見える。上下端ギリギリまで使わない）
- ファイル名・IDは **lower-kebab-case**（`a-z0-9` とハイフンのみ）
- 絵柄は `docs/monster-style-guide.md` の **BugBash House Style Lock** 準拠
  （AI生成ならプロンプト先頭に貼る。3/4角度・やや左向き）
- 置き場所: このリポジトリの `game-assets/source/` 配下（下記各項）。
  置いてくれれば webp変換・R2アップロード・マニフェスト登録・UI組み込みは
  すべてこちらでやる。**ファイルだけ渡してくれるのでも良い**

## P1. 勇者（2枚）

いちばん露出が多いのに1枚も無い。

| # | 内容 | 規格 | 使う場所 |
|---|------|------|---------|
| 1 | 勇者の立ち絵（全身） | 1254×1254 PNG 透過 | ログイン画面・公開プロフィール・共有OGP画像 |
| 2 | 勇者の顔アップ（バストアップ可） | 512×512 PNG 透過 | サイドバーのアバター(32px)・プロフィール(76px) |

- モチーフ: 「エンジニアの勇者」。ターミナル緑（#7ee787）をアクセントに、
  フーディ+剣/キーボードなど、House Style Lock のかわいい寄りで
- **備考**: `public/hero.png`（1024²・非透過）と `public/hero_toka.png`
  （598×746・透過）が未使用のまま置いてある。これが勇者案なら新規発注は不要 —
  どちらを採用するか言ってくれれば組み込みまでやる（透過の方が扱いやすい）

## P2. アプリアイコン / ファビコン（1枚）

現状 Next.js のデフォルトファビコンのまま。

- **1024×1024 PNG**（透過不要・背景あり可）。角丸は付けない（OS側で付く）。
  主要モチーフは中央に、周囲に約12%の安全余白
- favicon.ico / apple-icon / PWAアイコンへの展開はこちらでやる

## P3. アイテムアイコン（最小10枚で25個ぶん埋まる）

ショップ・インベントリ・召喚結果のアイコン。現状は絵文字/CSS図形フォールバック。
**表示は 20〜48px が主戦場**なので、小さくても読める強いシルエットが最重要。

単品7種（`game-assets/source/items/{itemId}.png`）:

| itemId | いまの絵文字 | 内容 |
|--------|--------------|------|
| `soul-pack-s` | 💠 | 魂パック小 |
| `soul-pack-m` | 💙 | 魂パック中 |
| `soul-pack-l` | 💜 | 魂パック大 |
| `evolution-stone` | 💎 | 進化の輝石 |
| `purification-proof` | 🌟 | 浄化の証 |
| `abyss-proof` | ⭐ | 深淵の証 |
| `commemorative-mint` | 🏅 | 記念鋳造 |

属性魂パック 18種（itemId = `{attribute}-soul-pack-{s|m|l}`）:

- 属性は `fire`(炎)・`water`(水)・`thunder`(雷)・`nature`(自然)・`light`(光)・`dark`(闇)
- **属性ごとのベース1枚 × 6属性 = 6枚**を描いてくれれば、S/M/L のサイズ差
  （数・光量など）はこちらで加工して18枚に展開できる。18枚全部描いても良い

## P4. スキン（1本目 = 6枚 / 1スキン）

**事業的に最重要**（収益の床 = パス + スキン）。ただし1スキンにつき6形態ぶん
必要で最も重いので、人気が出そうな系統1つから始めるのがおすすめ。

- **厳格仕様（ビルドが検査する）**: PNG 1254×1254 RGBA・6形態
  （`base` / `evo` / `awakened` / `awakened-final` / `berserk` / `berserk-final`）
  が**全部揃っていないとビルドが落ちる**
- 置き場所: `game-assets/source/monsters/{slug}/skins/{skinId}/{stage}.png`
  - 例: `monsters/null-pointer-axolotl/skins/midnight-neon/base.png`
- デザインの約束: **同じモンスターの衣装替え**に見えること。体型・ポーズは
  素体準拠、色・衣装・小物で差別化（ショップで「変身前/変身後」を並べて見せる）
- 入稿されたら: BEのシード登録（現在は実アート待ちで意図的に空）・
  価格設定・ショップのスキン導線復帰までこちらでやる

## 入稿から反映までの流れ（参考）

1. `game-assets/source/…` にPNGを置く（またはファイルをそのまま渡す）
2. `npm run assets:publish:r2` — webp変換（品質82・原寸維持）と
   `asset-manifest.json` 生成・R2アップロードまで自動
3. マニフェストに載った時点でBEがURLを返し始め、UIに出る（キャッシュ5分）

スキンだけは追加でBEシード＋価格設定が要る（こちらの作業）。
